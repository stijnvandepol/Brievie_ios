# iOS Ordenen (fase 1c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In the app the post has an inbox and can be filtered per person; a letter shows on whose name it is and which labels it has; the review screen offers the server's proposals for addressee and labels (a recognised name already ticked) and confirms them with the rest; a confirmed letter can be put on another name, relabelled and its tasks ticked off; open tasks with a deadline appear in a calendar on the phone.

**Architecture:** The `DocumentServer` seam and `WorkspaceDocuments` grow with persons, labels, suggestions and tasks; screens keep talking to `WorkspaceDocuments` only. `FeatureDocuments` gets an organise section shared by the review and the confirmed document. The calendar is a new group in `BrievieCore` (`Calendar/`): a pure planner that compares open tasks with the events of the workspace's own calendar, behind a `CalendarStore` protocol with an EventKit implementation. There is no local table of tasks and events: the calendar is the state.

**Tech Stack:** As in 1b (Swift 6 strict concurrency, SwiftUI, iOS 18+, XcodeGen, swift-openapi-generator 1.12.2, Swift Testing, SwiftLint), plus EventKit. No new package dependency.

**Spec:** `../Brievie_host/docs/superpowers/specs/2026-11-16-fase-1c-ordenen-design.md` (the design; "D 15" below is its section 15). Host plan: `../Brievie_host/docs/superpowers/plans/2026-11-16-host-fase-1c.md` (its Tasks 2, 3, 5, 8 and 15 define the contract used here). Previous plan: `docs/superpowers/plans/2026-11-14-ios-fase-1b.md`.

## Decisions taken with the owner (2026-11-16)

- Post is on the name of a person; everyone in the workspace sees everything (no private documents yet).
- A proposal from the AI or from a rule is never ticked by itself; a name recognised in the letter with a strong sign (server field `preselected`) is.
- Deadlines go into the phone's calendar through EventKit, not through an ICS feed.
- Not in the app in 1c: the Today screen and the tab bar, local notifications, history and undo, managing labels and rules (those are in the web).

## Global Constraints

- Everything in `CLAUDE.md` and in the Global Constraints of the 1a and 1b plans holds: English code, Dutch B1 je-vorm text only through the String Catalogs (in `FeatureDocuments` through `DocumentStrings`; the parity tests stay green), Swift 6 with `async/await` only, no `!`/`try!`/`as!` outside tests, dumb views, HTTPS only, VoiceOver and the largest Dynamic Type on every screen, `project.yml` is the source and `make generate` output is committed.
- No API type written by hand: features see only the models in `BrievieCore`; the generated types stay inside `LiveBrievieServer`.
- API v1 is additive: an unknown `inbox_state`, suggestion `action`, `origin` or label colour never breaks decoding. Unknown actions are not shown; an unknown colour is grey.
- A label is always shown with its name; colour is never the only signal.
- AI proposals are marked as such (spec 14): a suggestion with origin `ai` carries the text "Voorstel van AI".
- No document content, names or label names in logs (`privacy: .private`).
- The app writes only in the calendars it made itself, and never without the switch being on.
- `BrievieCore` compiles for macOS so `make test` runs it; EventKit code that needs iOS behaviour sits behind the `CalendarStore` protocol.
- Work on branch `feat/fase-1c`, from `main`. Conventional commits, trailer `Co-Authored-By: Claude <noreply@anthropic.com>`. Do not push. iCloud makes conflict copies with " 2" or " 3" in the name (also inside source folders, which breaks the build): never commit one; move them aside when a build fails oddly.

## Review Focus

1. The server is still on 1b (no persons, labels or suggestions in its answers), or the app is older than the server: lists and review must work without the new fields, and a confirm from this app against a 1b server must not fail. → Task 1 (`decodesDocumentWithoutOrganiseFields`, `confirmSendsOrganisationWhenSet` asserts the body still holds every 1b field), Task 2 (`a1bServerWithoutPersonsStillShowsThePost`), Task 3 (`confirmAgainstA1bServerSendsNoOrganisation`). The 1b server's input schemas ignore JSON fields they do not know, so the extra confirm fields do no harm there.
2. A person or label was deleted or archived on the server while the review was open: confirm answers 404 for that id; the app must say so, reload the lists and keep the rest of the draft. → Task 3.
3. Calendar access is refused, later withdrawn in Settings, or the user deletes the Brievie calendar: no crash, no events in another calendar, a clear line under the switch, and the next sync makes the calendar again only while the switch is on. → Task 5.
4. The same task is synced twice at once (the app becomes active while a confirm also triggers a sync), or a sync is interrupted halfway: never two events for one task. → Task 5 (`concurrentSyncsCreateOneEvent`, `planRemovesDuplicateEventsOfOneTask`).
5. A long name or twenty labels at the largest Dynamic Type size: chips wrap, nothing is cut off, every chip is reachable with VoiceOver. → Tasks 2 and 6.

### Task 5: Deadlines in the calendar

**Files:**
- Create: `BrievieCore/Calendar/{CalendarModels,CalendarSyncPlanner,CalendarStore,EventKitCalendarStore,CalendarSettings,CalendarSync}.swift`, `FeatureWorkspace/CalendarSettingModel.swift`
- Modify: `FeatureWorkspace/{WorkspacesView,WorkspaceStrings}.swift` and its catalog, `App/{Info.plist,AppEnvironment.swift,RootView.swift,Localizable.xcstrings}`, `BrievieCore/App/Unpairing.swift`, `project.yml` when the plist keys live there (then `make generate`), `docs/DECISIONS.md`
- Test: `Tests/BrievieCoreTests/{CalendarSyncPlannerTests,CalendarSyncTests,CalendarSettingsTests}.swift`, `Tests/FeatureWorkspaceTests/CalendarSettingModelTests.swift`

**Interfaces:**
- Produces in `CalendarModels.swift` (`Equatable, Sendable`):
  - `struct CalendarTask { id: UUID; title: String; notes: String; day: CalendarDate }`
  - `struct CalendarEventSnapshot { eventID: String; taskID: UUID?; title: String; notes: String; day: CalendarDate }` (`taskID` parsed from the event's URL `brievie://task/<uuid>`; nil for an event the user added by hand)
  - `enum CalendarChange { case create(CalendarTask), update(eventID: String, CalendarTask), delete(eventID: String) }`
- Produces: `enum CalendarSyncPlanner { static func plan(tasks: [CalendarTask], events: [CalendarEventSnapshot], window: ClosedRange<CalendarDate>) -> [CalendarChange] }`, pure:
  - a task inside the window without an event → `create`; with one event that differs in title, notes or day → `update`; equal → nothing;
  - an event with a `taskID` that is not among the tasks → `delete`; several events with the same `taskID` → keep the first, `delete` the rest;
  - an event without a `taskID` is never touched; a task outside the window gets nothing (and its event, if it is inside the window on an old date, is deleted like any event that no longer matches).
- Produces: `static func CalendarTask.from(_ task: WorkspaceTask, typeTitle: (String) -> String) -> CalendarTask?` (nil when there is no deadline or the task is done): title "<taaksoort>: <omschrijving>", notes "<afzender>\nUit Brievie" (only "Uit Brievie" without a sender).
- Produces: `protocol CalendarStore: Sendable`:
  ```swift
  func access() async -> CalendarAccess                     // .granted, .denied, .notDetermined
  func requestAccess() async -> CalendarAccess
  func ensureCalendar(named: String, existingID: String?) async throws -> String   // the calendar's identifier
  func events(calendarID: String, window: ClosedRange<CalendarDate>) async throws -> [CalendarEventSnapshot]
  func apply(_ changes: [CalendarChange], calendarID: String) async throws
  func removeCalendar(id: String) async throws
  ```
  `EventKitCalendarStore` (an actor around one `EKEventStore`): `requestFullAccessToEvents`; `ensureCalendar` returns the calendar with `existingID` when it still exists, else one with the same title in the default source, else a new one there; all-day events, `url = brievie://task/<id>`, alarms at 7 days and 2 days before and on the day, each at 09:00 local time (`EKAlarm(relativeOffset:)` from the start of the all-day event: −7 d + 9 h, −2 d + 9 h, +9 h); `apply` commits once at the end. `FakeCalendarStore` in the library keeps calendars and events in memory and can be told to refuse access or to fail.
- Produces: `protocol CalendarSettings: Sendable { func calendarID(for workspace: UUID) -> String?; func isEnabled(for workspace: UUID) -> Bool; func enable(workspace: UUID, calendarID: String); func disable(workspace: UUID); func removeAll() }` with `UserDefaultsCalendarSettings` (keys `calendar.<workspace-uuid>`; the value is the calendar identifier: not a secret). This is the second sanctioned use of `UserDefaults`: record it in `docs/DECISIONS.md`. `Unpairing` calls `removeAll()` (the calendars themselves stay; pairing again finds them by title).
- Produces: `actor CalendarSync`:
  - `init(store: any CalendarStore, settings: any CalendarSettings, tasks: @Sendable (UUID) async throws -> [WorkspaceTask], workspaceName: @Sendable (UUID) -> String, today: @Sendable () -> CalendarDate)`
  - `func sync(workspace: UUID) async -> CalendarSyncResult` (`.off`, `.noAccess`, `.done(created:updated:deleted:)`, `.failed`): does nothing when the switch is off or access is not granted; window = one year back to three years ahead; a second call while one runs for the same workspace waits for it and then runs once more (never two in parallel).
  - `func enable(workspace: UUID) async -> CalendarSyncResult` (asks for access, ensures the calendar "Brievie – <werkruimte>", stores it, syncs) and `func disable(workspace: UUID, removeCalendar: Bool) async`.
- `CalendarSettingModel` (per workspace row): `isOn`, `message` ("Brievie mag niet bij je agenda. Zet het aan in Instellingen." with an "Open Instellingen" action when access is refused), `toggle(_:)`; switching off asks "Agenda 'Brievie – <naam>' ook verwijderen?" with "Verwijderen" and "Laten staan".
- `WorkspacesView`: under each workspace a switch "Zet deadlines in mijn agenda" with the footer "Je taken met een datum komen in een eigen agenda 'Brievie'. De tekst van de taak en de afzender staan erin, ook als je agenda met iCloud synchroniseert."
